# Видеонаблюдение

Раздел доступен по умолчанию владельцу и администраторам. Владелец может изменить доступ в карточке сотрудника через список разделов. Наличие доступа к разделу позволяет видеть все торговые точки; закрепление точек за администраторами и расчет их зарплаты не меняются.

## Подключение

В карточке торговой точки, в блоке «Видеонаблюдение», включите нужные камеры (до четырех), задайте названия и RTSP-ссылки, затем нажмите «Сохранить камеры». Настройка доступна владельцу и администраторам с доступом к торговым точкам. Оператор берется из существующего поля карточки.

Ссылки должны вести на доступный из интернета RTSP-сервер с публичным IPv4-адресом и поддержкой RTSP over TCP. Адреса локальной сети, например 192.168.x.x, с Vercel недоступны. Не открывайте камеры в интернет без защиты: предпочтителен RTSP, предоставленный облачным оператором, и отдельная учетная запись только для просмотра. RTSP не шифрует транспорт. Поддержка RTSPS и постоянной видеотрансляции потребует другого подключения.

Для Ozon Видео необходима именно RTSP-ссылка, полученная у оператора. Обычная ссылка на личный кабинет не является видеопотоком. Без RTSP или API оператора невозможно достоверно определить доступность изображения/облачного архива. Автоматического входа в личный кабинет Ozon нет.

## Что проверяется

- Получение и декодирование одного свежего JPEG-кадра с камеры через FFmpeg. Это периодические снимки, не непрерывное видео.
- Проверка запускается при открытии раздела, вручную и автоматически примерно раз в минуту после окончания предыдущего цикла, пока раздел открыт и вкладка видима. Проверяются выбранные точки с учетом администратора. Статус-фильтр не исключает камеры из проверок, чтобы восстановившиеся камеры могли вернуться в список.
- «Доступно»: получен кадр. «Нет изображения»: соединение, авторизация или декодирование не удались. «Не проверено»: нет свежего результата или недоступен сервис проверки. «Нет RTSP»: ссылки не заданы. Через 3 минуты результат считается устаревшим.
- Доступность архива и самого облачного кабинета отдельно не проверяется. Фоновый круглосуточный мониторинг и уведомления вне открытой страницы не включены.

## Хранение и защита

Настройки и последние результаты сохраняются в текущем хранилище приложения (в production: Supabase `app_kv`) в отдельных записях `surveillance_config_<sha256(pointId)>.json` и `surveillance_status_<sha256(pointId)>.json`. Новые SQL-таблицы не нужны. При недоступной базе возвращается ошибка; временное сохранение в памяти не считается успешным.

RTSP-ссылки могут содержать пароли. Они не возвращаются в API списков/карточек, не передаются браузеру после сохранения, не включаются в AI-контекст и аудит. При повторном сохранении пустое поле замены сохраняет старую ссылку; снятие флажка удаляет подключение. База и service-role ключ должны оставаться закрытыми.

Кадры доступны только авторизованным пользователям с доступом к разделу, имеют `Cache-Control: no-store`, в базе не сохраняются. Временный кеш в памяти процесса ограничен 12 точками; повторные проверки ограничены интервалом 45 секунд. Кадры не отправляются на Google Drive или сторонние сервисы. Подпроцесс FFmpeg не получает переменные окружения Supabase/SMTP/Google.

Сетевой посредник фиксирует проверенный публичный IP, блокирует RTSP-переадресации, возвращает абсолютные адреса управления из SDP на локальный посредник; FFmpeg работает только с RTSP/TCP. Получение кадра ограничено таймаутом и размером. В аудит попадают изменение конфигурации и переходы состояния камер, без URL и изображений.

## Эксплуатация

`npm ci` устанавливает `ffmpeg-static` для платформы сборки; не копируйте `node_modules` с Windows на Linux. Vercel включает Linux-бинарник через `includeFiles`, длительность функции установлена 60 секунд. Одновременно браузер проверяет две точки; внутри точки камеры обрабатываются последовательно. Автообновление потребляет лимиты Vercel и трафик RTSP-оператора, поэтому лишние точки можно снять с выбора или отключить автообновление.

Проверки: `npm test`, `npm run smoke`. Тесты используют изолированное хранилище и синтетические данные, не подключаются к реальным камерам.

Первичные источники: [FFmpeg RTSP](https://ffmpeg.org/ffmpeg-protocols.html#rtsp), [ffmpeg-static](https://github.com/eugeneware/ffmpeg-static), [ограничения Vercel Functions](https://vercel.com/docs/functions/limitations).
